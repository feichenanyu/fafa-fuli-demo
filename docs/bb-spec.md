# \*\*采 首期产品 Spec v0.2

Oct 27, 2026 · @sanyuan

## 一、背景与目标

\*\*采是采发发面向**企业终端采购人员**的 AI 采购产品：用户说一句需求，AI 助手「小帮」追问 1–2 个关键问题，从\*\*采商品库里配出 2–3 套方案，用户确认后用预付款下单。它从发发福利 v1.1 精简而来，去掉了服务商侧的利润、合规画像、权益包细分和活动账户。

- **服务对象**：10–200 人企业里兼职做采购的行政、办公室、工会人员，一人要管福利、行政、办公三类采购；不懂供应链，需要「省心、能报给领导」。
- **和发发福利的关系**：两者共用平台底座（客户、订单、账户、供应链接入）和同一个运营管理后台；\*\*采有**独立的商品库、定价规则和场景运营**，在后台作为一个新应用「\*\*采」管理。
- **首期目标**：让终端采购人员从说需求到拿到可下单的方案 ≤ 3 分钟、≤ 3 轮对话；商品上下架和会员价由规则自动完成，运营只做例外处理。

配套文档：《\*\*采 PRD》《\*\*采 AI 选品 Prompt》；对话话术沿用[《帮你采 · 小帮对话话术规范》](https://claude.ai/artifact/V5AnFRDvoUWqfML7kGUHv7)；Demo 见画布「\*\*采 Demo v0.2」与「运营管理后台 Demo v1.2」。

## 二、首期范围

首期做「一套商品库 + 三大应用对话 + 预付款下单」的最小闭环，其余留到后续。

| 模块 | 首期做 | 首期不做 |
| --- | --- | --- |
| 商品库 | 独立商品库；按「自动上下架规则」从京东自营 / 天猫超市 / 1688 / 得力直供 / 供应商直供自动上品、自动下架；运营可手动下架 / 恢复自动 | 商品类型（爆品 / 礼包 / 卡券）区分；人工审核上架流程；礼包组合运营 |
| 定价 | 商品库级定价规则：类目 / 品牌 / 货源 / 市场价利润率区间 → 加价率，默认加价、底价、顶价、取整；上架即自动定会员价 | 会员等级折扣；场景价；单品改价 |
| 前台首页 | 沿用发发福利 Agent UI；手机号验证码登录页（未注册自动注册）；左侧菜单（新建任务 / 订单管理 / 任务列表 / 用户卡）；三大应用切换（福利 / 行政 / 办公采购）；子场景、快捷语、热门运营场景由后台配置；未完成任务提醒 | 商品频道 / 频道装修；全站搜索列表页 |
| AI 任务 | 三栏任务页：中间 AI 工作流（loop 追问 + 选择卡 + 思考过程，不放操作按钮），右侧产出物（方案 / 选品清单筛选 / 汇报 / 下单） | 审批流（钉钉 / OA）；多人协同编辑同一任务 |
| 产出物 | 改数量 / 换一款 / 移除；导出清单（Excel）；生成汇报方案（PPT / 分享页，分享前确认） | 报价单盖章；多方案对比导出 |
| 交易 | 下单确认卡；统一送公司 / 按名单代发（仅福利）；专票 / 普票；预付款 / 微信 / 支付宝支付，预付款不足可用微信 / 支付宝补差；下单前须完成企业认证 | 活动账户抵扣；赊销 / 账期；购物车 |
| 账户 | 手机号账号 + 企业认证（上传营业执照）；预付款账户（仅对公汇款智能认账充值）、AI 积分；与发发福利一致保留订单管理（按货源拆子单）、账号信息、企业认证、组织管理、企业信息、预付款管理、结算与账单 | 活动账户 |
| 运营后台 | 在同一后台新增应用「\*\*采」：商品库（商品 / 自动上下架规则 / 定价规则）、场景运营（子场景 / 三大应用）、热门运营场景、应用设置；顶栏业务线可切到\*\*采 | 独立的\*\*采后台、独立账号体系 |

## 三、关键产品决策

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | \*\*采使用**独立商品库**，不复用发发福利的商品池 | 终端企业的品类（行政 / 办公）和价格策略与服务商渠道不同，独立才能单独控制上品范围与加价 |
| D2 | 商品**不区分商品类型**，只用类目、品牌、货源 | 终端用户不关心爆品 / 礼包 / 卡券；卡类作为「礼品卡」类目处理 |
| D3 | 上下架**全部由规则自动完成**，运营只做「手动下架 / 恢复自动」例外 | 商品量级大、变化快；规则之间是「或」，命中任一启用规则即上架 |
| D4 | 会员价 = 接口价 ×（1 + 加价率），加价率来自商品库定价规则（自上而下命中第一条，都不命中用默认） | 与发发福利商品池定价口径一致；\*\*采只有一套业务系统，所以只有一套规则 |
| D5 | 前台 AI 对话框分「福利采购 / 行政采购 / 办公采购」三大应用，应用固定，**子场景由后台运营** | 三类覆盖终端采购高频需求；子场景（春节 / 生日 / 餐补 / 茶水间…）随季节变化 |
| D6 | 任务页三栏：左菜单、中间 AI 工作流、右侧产出物与操作区 | 对话只放问答、思考过程和澄清选择；下单、重配方案、汇报、导出只在右侧执行；右侧修改在对话中留痕 |
| D7 | 小帮按 loop 工作：观察（已知 / 缺失）→ 判断（问还是出方案）→ 行动；最多追问 2 轮、每轮 ≤ 2 问 | 减少来回；问不到的用场景默认值并告知 |
| D8 | 下单、付款、分享**必须用户点确认卡**，小帮不自动执行 | 金额与数量不出错；「由 Agent 干活、人来把关」 |
| D9 | 只开通预付款账户和 AI 积分，**不开通活动账户**；预付款只支持对公汇款到专属账号、智能认账，暂不支持在线充值；下单可用微信 / 支付宝全额付款或补差 | 首期没有平台出资活动；积分仅用于 AI 功能（出方案 5、生成汇报 10），不抵货款 |
| D10 | \*\*采运营在同一运营管理后台，作为「业务应用」下新增应用 | 客户、订单、财务、权限复用平台底座，只新增应用层 |

## 五、验收标准

以下条目全部可在 Demo 上复现，按 P0 验收。

**对话与方案**

- [ ] 输入「给 20 个人准备春节福利，人均 200 元」：只追问 1 个问题（到货时间），回答后出 3 套方案并标首推。
- [ ] 用户说过的人数 / 预算 / 到货 / 品牌不会被再问；追问最多 2 轮、每轮 ≤ 2 问。
- [ ] 点「不确定，你先推荐」或说「随便」：不再追问，按默认值出方案，并在回复中说明用了常用值。
- [ ] 方案内商品全部是\*\*采商品库已上架、有货、能在要求时间内送达的商品；库存不够的在处理过程里写明「只剩 N 件、已换同类」。
- [ ] 方案回复按「结论 → 理由 → 下一步」，含总价 / 人均、与预算差额、送达日期；对话里不带任何操作按钮，导出、汇报、下单都在右侧。
- [ ] 超出平台范围（如机票）不硬推荐；需求模糊（如「买点东西」）给子场景选项。

**右侧产出物**

- [ ] 改数量 / 换一款 / 移除后，总价、预算条、送达日期立即更新；对话中出现一条留痕，连续修改只保留最新一条；切换 A / B / C 方案只更新右侧，不在对话中留痕；超预算时提示可在右侧点「更省钱」重配。
- [ ] 选品清单筛选只显示当前子场景类目内的商品；无货商品不能加入方案。
- [ ] 生成汇报：在右侧「汇报」选格式；分享页必须点「确认无误，生成分享链接」后才生成链接；扣 10 积分。

**下单**

- [ ] 下单只在右侧「下单」页签完成：提交后原位展开确认卡，不点确认不生成订单；对话中不出确认按钮。
- [ ] 预付款充足：扣预付款，用户菜单余额与资金流水同步更新；不足：确认卡显示补差金额，提供 \[在线支付补差并下单\] \[先去充值预付款\]。
- [ ] 手机号 + 验证码可直接登录，未注册自动注册；未认证账号可出方案、做汇报，提交订单时进入企业认证，上传营业执照审核通过后自动回到下单页；充值弹窗只支持汇款智能认账（民生 / 招商专属账号），在线充值提示暂不支持；下单支付可选预付款 / 微信 / 支付宝。无任何活动账户入口或抵扣项；订单按货源拆成子单，确认收货后进入「结算与账单」，可勾选申请开票。

**运营后台**

- [ ] 后台左侧「业务应用」下出现「\*\*采」，含商品库 / 场景运营 / 热门运营场景 / 应用设置；顶栏业务线可切到\*\*采。
- [ ] 停用一条上品规则后，只靠它上架的商品变为「已下架」并写明原因。
- [ ] 新增 / 调整定价规则顺序后，商品库的会员价和「定价命中」列立即变化；会员价不低于底价，底价高于市场价的商品自动下架。
- [ ] 子场景保存校验：至少 1 个类目；必填维度必须在追问维度里；快捷语 ≤ 4 条。有上线热门场景引用的子场景不能删除。

## 六、成功指标

上线后 8 周内按下表评估，目标值为初版假设，第一个月数据出来后校准。

| 指标 | 口径 | 目标 |
| --- | --- | --- |
| 出方案率 | 发起任务中拿到至少 1 套方案的占比 | ≥ 85% |
| 平均追问轮数 | 出方案前小帮追问的轮数 | ≤ 1.5 |
| 方案到下单转化 | 出方案的任务中 7 天内下单的占比 | ≥ 25% |
| 首推采纳率 | 下单方案 = 小帮首推方案的占比 | ≥ 50% |
| 右侧修改率 | 下单前至少改过 1 次数量 / 商品的占比 | 观察，用于调优选品规则 |
| 自动上下架覆盖 | 商品库中由规则自动上下架的占比（非手动下架） | ≥ 95% |
| 价格异常 | 会员价 > 市场价或 < 底价仍在架的商品数 | 0 |

## 七、依赖、风险与待确认

**依赖**：供应链接口提供接口价、市场价、库存（部分仅三档状态）、近 30 天销量、配送时效；平台底座的企业认证、预付款、订单与发票；AI 工具接口 search\_goods / build\_plan / quote（见《AI 选品 Prompt》）。

**风险**

- 部分供应链没有市场价 → 利润率条件失效。应对：没有市场价的商品按「市场价 = 会员价 × 1.3」估算并在商品库标注，待确认。
- 自动上品范围过宽引入低质商品 → 规则带月销下限和排除品牌；上线初期每周抽检新上架商品。
- 小帮默认值与用户预期偏差大 → 回复中必须说明用了哪些常用值，且可一句话修正。

**待确认**

- [ ] 商品池定价的业务系统里已有「企业终端采购」；\*\*采改为独立商品库后，该选项是否去掉？（建议：去掉，避免两套价）
- [ ] AI 积分是否与发发福利共用同一额度，还是\*\*采单独发放？消耗标准（出方案 5 / 汇报 10）由 AI 团队确认。
- [ ] \*\*采企业认证审核走人工还是接入第三方工商核验？审核时效、驳回原因清单？（已定：手机号可直接登录使用，下单前必须完成企业认证）
- [ ] 各子场景默认值（福利人均 200、行政人数 30 等）与加价率均为演示数字，待商务确认。
- [ ] 接入钉钉 / OA 后，「生成汇报」是否改为「提交审批」。
