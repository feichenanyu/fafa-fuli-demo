## 一、文档说明

### 1.1 背景与定位

发发福利前台（Beta 0.3）的栏目、频道、页面装修、专题、商品池、引导词和商品范围都由平台运营人工配置；企业认证、权益、资金、订单和售后也需要平台侧处理。

本后台定位为**采发发全平台共用的运营管理后台**：客户、商品、交易、账户与财务、数据与智能、系统设置作为**平台底座**只做一份；各业务线（发发福利、发发集采、分采通…）以**业务应用**形式接入，各占一个一级菜单。首期接入发发福利。

### 1.2 范围

- 平台底座：客户中心、商品中心、交易中心、账户与财务（积分入口 / 活动 / 商品预付款 / 发票）、数据与智能（AI 应用、定时任务、埋点）、系统设置。
- 业务应用·发发福利：场景管理、频道运营、专题管理、广告位、价格与利润策略。
- 不在本期：供应商入驻与招商（移到商家端）、H5 / 页面类资源、发发集采与分采通的业务应用内容（只预留插槽）、积分规则（AI 开发团队负责）。

### 1.3 使用角色

| 角色 | 职责 | 培训流程 |
| --- | --- | --- |
| 超级管理员 | 后台账号、角色与权限、业务线、系统参数 | — |
| 客户运营 | 企业认证审核、客户标签、权益开通、账号维护、集采咨询跟进 | 11.1 |
| 商品运营 | 商品库、标准化、标签与标签类型、商品池、频道商品归置、异常商品、商品监控任务 | 11.2 |
| 内容运营 | 场景与场景层、引导词、场景 / 频道页面装修、专题、广告位 | 11.3 |
| 财务 | 充值认账、发放与调账复核、退款复核、发票、对账 | 11.4 |
| 订单 / 客服 | 订单跟进、售后介入与裁定、订单监控任务 | 9.2 |
| 产品 / 数据 | 埋点字典与上报质量、埋点监控任务、数据看板、AI 应用效果评估 | 十四 |

### 1.4 与前台文档的关系

- 前台以《发发福利 PRD v2.0》和 Beta 0.3 Demo 为准；AI 行为以《AI Prompt 设计 v2.0》为准；前台埋点以本文第十四节为准。
- 前台不得出现后台无法配置的运营内容；前台新增可交互元素必须同步补埋点。

### 1.5 已定规则（沿用）

- 个人账号可注册、浏览，不可下单；不展示成本、会员价、利润率。
- 积分账户 = AI 功能消耗的 token，规则由 AI 开发团队制定，后台只保留入口。
- 收款主体与开票主体为同一家公司。
- 默认利润率 15%、线上充值单笔上限 ¥50,000、售后供应商先审平台介入（均待确认）。

### 1.6 数据归属原则：身份和钱共用，权益分业务线

| 对象 | 归属 | 说明 |
| --- | --- | --- |
| 企业客户、认证、子账号 | 全平台唯一 | 认证一次，各业务线通用 |
| 商品预付款账户 | 全平台一个余额 | 每条流水带业务线，对账可按业务线拆分 |
| 活动账户 | 发放时指定可用业务线 | 默认只限发起活动的业务线 |
| 积分账户（AI token） | 平台级 | 规则归 AI 开发团队 |
| 会员等级、权益包 | 按业务线开通 | 各业务线价格体系与可见货源不同 |
| 商品库 | 平台唯一 | 各业务线从同一商品库取品，商品可标记适用业务线 |
| 订单、售后、发票、埋点事件 | 底座统一管理 | 均带「业务线」字段，可按业务线筛选与统计 |

### 1.7 术语

| 术语 | 含义 |
| --- | --- |
| 业务线 | 接入后台的业务应用，如发发福利、发发集采、分采通 |
| 栏目 | 发发福利前台固定一级：福利场景 / 商品资源 / 专家咨询 |
| 场景频道 / 资源频道 | 栏目下的二级，如新春年货节；电商精选（京东自营） |
| 专题 / 商品池 | 商品池：运营按规则维护的通用商品集合，供场景 / 频道 / 专题引用；专题：规则 + 商品池 + 排他规则圈出的一组商品 + 落地页 |
| 页面装修 / 坑位 | 场景页 / 频道页的 PC 版式：模板决定固定板块，每个坑位链接专题、品牌商品列表或自定义图片 + 链接 |
| 排他规则 | 专题里打开「排他」的规则：它命中的商品从专题结果中剔除 |
| 会员价 / 利润差价 | 企业会员采购成本价；对客价 − 会员价 |
| 权限点 | 一个可授权的菜单、按钮或字段，如 trade.order.export |
| 埋点事件 | 一次用户行为的上报记录，如 fafa\_res\_card\_click |

### 2.2 权限模型：四层授权

角色不写死在代码里，由超管在「角色与权限」中组合以下四层：

| 层 | 管什么 | 例子 |
| --- | --- | --- |
| 功能权限 | 菜单与按钮（权限点） | 能看订单列表，但没有 trade.order.export（导出） |
| 业务线范围 | 能操作哪些业务线 | 发发福利内容运营只能改发发福利的场景与频道 |
| 数据范围 | 全部 / 本部门 / 本人负责的客户 | 首期默认「业务线 + 本部门」；「本人负责的客户」依赖 P1 客户归属 |
| 字段权限 | 敏感字段可见 / 脱敏 / 不可见 | 接口价、成本、利润率只给商品运营和财务；手机号、信用代码默认脱敏 |

规则：一个账号可绑多个角色，功能与范围取并集；新账号默认无权限；系统预置 7 个角色模板（1.3 中的角色），超管可复制后修改，新增角色无需发版。

### 2.3 安全底线

- **资金操作双人复核**：人工调账、冻结 / 解冻、退款、活动发放、认领流水均为一人发起、另一人复核，发起人不得自审。
- **高危权限单独授予**：资金、导出、角色管理、敏感字段明文标记为高危，授予时须超管发起 + 另一超管确认。
- **导出管控**：单次超过 1,000 条走审批；导出文件带操作人水印；导出记录可查。
- **明文查看留痕**：敏感字段点「查看」才显示明文，每次记日志。
- **账号安全**：强制二次验证；离职一键停用；90 天未登录自动停用；登录 IP 与时段限制（P2）。
- **AI 不执行**：AI 只给建议，资金、售后裁定、上下架、发布均须人工点击确认。

### 2.4 操作日志

所有写操作、导出、明文查看、角色与权限变更、AI 建议采纳均记录：操作人、时间、业务线、模块、对象 ID、变更前后值、IP；可按模块 / 操作人 / 时间查询导出；资金与权限类日志不可删除。

## 三、用户管理

### 3.1 用户列表

- **筛选**：账号类型（个人 / 企业）、认证状态、会员等级、标签、所属地区、注册时间、最近下单时间、账号状态；关键字搜索手机号 / 企业名 / 统一社会信用代码。
- **列表字段**：用户 ID、主账号手机号（脱敏）、企业名称、账号类型、会员等级、三个账户余额、累计订单金额、注册时间、状态。
- **操作**：查看详情、打标签、调整会员等级、冻结 / 解冻账号、重置登录、导出。

### 3.2 用户详情

分页签：基本信息｜企业认证｜子账号｜权益｜账户与流水｜订单｜售后｜操作记录。各页签数据与对应模块同源，可跳转到对应模块处理。

### 3.3 企业认证审核

个人账号上传营业执照申请升级，进入审核队列。

| 审核项 | 规则 |
| --- | --- |
| 营业执照 | OCR 识别企业名称、统一社会信用代码、法人、有效期，运营核对原图 |
| 工商核验 | 调用工商接口核验存续状态；吊销 / 注销直接驳回 |
| 重复校验 | 同一信用代码已绑定其他主账号时，提示「加入已有企业作为子账号」 |
| 结果 | 通过：账号类型变为企业，开通默认权益包与三个账户；驳回：必填原因（模板：图片不清晰 / 信息不一致 / 企业状态异常 / 其他），短信通知 |
| 时效 | 工作日 2 小时内处理；超时在工作台标红 |

审核状态：待审核 → 已通过 / 已驳回（可重新提交）；营业执照到期前 30 天提醒用户更新，过期后暂停下单但不影响已有订单售后。

### 3.4 子账号

- 企业主账号可在前台邀请子账号；后台可查看、停用子账号，但不替企业新增。
- 子账号权限项：可下单、可用哪些账户支付、单笔上限、是否可见利润。

### 3.5 用户标签

- 手工标签：运营新建（如「重点客户」「银行客户」），可批量打标。
- 规则标签：按条件自动归类（近 90 天下单金额、常买品类、场景偏好），每日更新。
- 用途：场景推荐、Banner 和专题的定向投放、权益包发放、活动账户发放。

### 3.6 冻结账号

冻结后不可登录与下单，余额冻结；已有订单继续履约。须填写原因并经复核（见 2.3）。

## 四、权益管理

权益决定一个用户「能看到什么价、能用哪些资源、能用哪些账户、享受哪些服务」。会员等级与权益包**按业务线开通**：同一企业可以是发发福利的企业会员、分采通的专业采购商。菜单位于客户中心；4.3 价格与利润策略位于各业务应用内。

### 4.1 会员等级

| 字段 | 说明 |
| --- | --- |
| 等级名称 | 如：个人用户 / 企业会员 / 专业采购商 / 大客户 |
| 升降规则 | 手动指定，或按近 12 个月采购额自动升级（阈值待确认） |
| 绑定权益包 | 每个等级绑定一个默认权益包 |
| 状态 | 启用 / 停用；停用前须把已有用户迁到其他等级 |

个人用户为系统预置等级，不可删除，其权益固定为：可浏览、不可下单、不展示成本与利润。

### 4.2 权益包

| 权益项 | 可配置内容 | 前台生效 |
| --- | --- | --- |
| 价格可见 | 显示会员价 / 零售价；是否显示市场价、利润率 | 商品卡、方案卡、频道页筛选 |
| 可用资源频道 | 勾选可见的资源频道与货源 | 商品资源栏目、AI 召回池 |
| 下单能力 | 可下单、可集采咨询、单笔上限 | 加购 / 立即下单 / 集采咨询 |
| 可用支付账户 | 活动账户 / 商品预付款、在线支付 | 结算页支付方式 |
| 服务费率 | 按货源设置（如妙鲤精选 5%） | 结算金额 |
| 专属服务 | 专属顾问、项目定制、经营概况分析 | 专家咨询栏目 |
| AI 积分 | 规则由 AI 开发团队制定，权益包中只引用其规则（如等级对应的赠送额度），见 5.2 | AI 对话框 |

权益包可按等级默认发放，也可按用户 / 标签单独发放，带生效与失效日期；同一用户有多个权益包时取并集，数值类取更优值。

### 4.3 价格与利润策略

- **默认利润率**：全局默认 15%，可按等级覆盖；用户可在前台 0%–40% 范围内自调，后台可改范围上下限。
- **预算口径默认值**：客户预算（client）/ 自己成本（self），默认 client。
- **价格保护**：会员价低于成本（亏本）的商品不进入前台，商品库标红提醒。
- 以上三项变更即时影响 AI 召回和方案测算，变更须复核。

## 五、账户与财务管理

企业认证通过后自动开通三个账户，全平台共用。三者不可互转，各自独立记流水，**每条流水带业务线**；商品预付款全平台一个余额，活动账户在发放时指定可用业务线。其中**积分账户不是支付账户**，只用于计量 AI 功能消耗。

### 5.1 三个账户对比

| 项 | 积分账户 | 活动账户 | 商品预付款账户 |
| --- | --- | --- | --- |
| 用途 | AI 功能消耗的 token（对话、方案生成、场景推荐等） | 平台出资的活动补贴，用于支付订单 | 企业自有资金预存，用于支付订单 |
| 规则制定方 | **AI 开发团队**（消耗标准、赠送、购买、有效期） | 平台运营 | 平台财务 |
| 来源 | 由 AI 开发团队定义 | 运营按活动发放 | 对公汇款认账、微信 / 支付宝在线充值 |
| 可否支付订单 | 否 | 是，限指定场景 / 频道 / 专题 / 商品 | 是，全站商品 |
| 可否退回 / 提现 | 由 AI 开发团队定义 | 不可 | 可申请退回原付款账户（须审核） |
| 发票 | 由 AI 开发团队定义 | 不开票 | 充值不开票，按订单实付开票 |

结算时默认扣款顺序：活动账户 → 商品预付款账户 → 在线支付补差；用户可在结算页取消勾选。

### 5.2 积分账户（保留入口）

积分规则由 AI 开发团队指定，运营管理后台本期只保留入口：

- 菜单位置：账户与财务 → 积分账户。
- 本期内容：按企业查看积分余额与消耗明细（字段与接口由 AI 开发团队提供）；规则配置页占位，标注「规则由 AI 平台管理」。
- 用户详情「账户与流水」页签展示积分余额，不提供调账。
- 与订单、售后、对账无关联。

### 5.3 商品预付款充值与认账

**对公汇款智能认账**

1. 用户在前台发起汇款充值，系统生成充值单与「汇款识别码」，提示汇款时填入附言。
2. 银行流水到账后自动匹配：识别码一致 → 自动入账；识别码缺失但付款方名称与已认证企业名一致、金额一致 → 建议匹配，财务确认；其余 → 进入「待认领」。
3. 待认领流水由财务手工认领到企业，须复核；认领错误可撤销（该笔款未被使用时）。
4. 超过 3 个工作日未认领的流水在工作台标红；无法归属的按原路退回流程处理。

**在线充值**：微信 / 支付宝，单笔上限 ¥50,000（待确认），支付成功即入账。

充值单状态：待汇款 / 待支付 → 待认账 → 已入账；或 → 已关闭（30 天未到账自动关闭）。

### 5.4 活动账户发放

- 运营新建活动：名称、预算总额、发放对象（指定用户 / 标签 / 等级）、单用户金额、使用范围（场景 / 频道 / 专题 / 商品）、有效期。
- 提交后须财务复核；发放后预算实时扣减，可提前终止（未使用部分收回）。
- 到期未用自动失效，失效前 7 天提醒用户。

### 5.5 人工调账与冻结

- 调账（仅活动账户、商品预付款账户）：增加 / 扣减，必填原因与关联单号，另一人复核后生效。
- 冻结：可冻结全部或部分金额；下单占用、售后待退由系统自动冻结 / 释放。
- 预付款退回：用户申请 → 财务审核 → 复核 → 原路退回；退回金额 ≤ 可用余额。

### 5.6 流水与对账

- 流水类型：充值、发放、下单扣款、售后退回、失效、人工调账、退回提现、冻结 / 解冻。
- 每条流水：流水号、账户、类型、金额、变动后余额、关联单号、操作人、时间。
- 日对账：每日按账户类型汇总期初、收入、支出、期末，与银行 / 支付渠道对平，差异项列出待处理；支持按企业导出对账单。

### 5.7 发票管理

**现阶段：人工上传**。用户申请开票 → 财务在外部开具 → 在后台上传发票文件并录入发票信息 → 系统通知用户下载。

**后续：对接财务系统**。开票申请自动推送到财务系统，开票完成后自动回传发票文件、号码与状态；人工上传保留为兜底。

| 功能 | 说明 |
| --- | --- |
| 开票申请 | 来自前台：用户对已完成的子订单申请；字段：发票类型（普票 / 专票）、抬头、税号、开户行与账号（专票）、收票邮箱 / 地址、开票金额 |
| 开票金额 | 子订单实付 − 已退款；礼包按子商品明细开具；活动账户抵扣部分是否开票待确认 |
| 人工上传 | 上传 PDF / OFD / 图片；录入发票代码、号码、开票日期、金额、税额；金额与申请不一致时提示确认 |
| 自动回传（后续） | 财务系统回传发票文件与信息，状态自动更新；回传失败进入「待人工处理」 |
| 驳回 | 抬头 / 税号有误时驳回，必填原因，用户修改后重新提交 |
| 红冲 / 作废 | 已开票子订单发生退款，自动生成红冲任务；财务上传红字发票后重新开具剩余金额 |
| 列表与导出 | 按企业、订单号、状态、申请时间、发票类型筛选；批量下载发票文件；导出开票台账 |

发票状态：待开票 → 开票中 → 已开票；分支：已驳回、待红冲 → 已红冲。超过 5 个工作日未开的申请在工作台标红。

## 六、场景管理

场景管理决定前台「精选福利场景」下每个二级场景的页面、引导词、AI 怎么答和卖哪些商品。内容运营在场景详情里按页签维护：引导词｜页面装修｜商品来源｜商品明细。

### 6.1 场景基本信息

新建场景只填 2 项，其余配置都在详情页签里完成。

| 字段 | 说明 | 前台生效 |
| --- | --- | --- |
| 场景名称 | 必填，如「新春年货节」；对话框上下文默认用此名称 | 场景频道栏、对话框上下文 |
| 有效期 | 开始日期 + 结束日期；常驻场景打开「长期有效」，不填结束日期 | 到期次日 0 点自动下线 |
| AI 反问与选品（选填） | 在「编辑基本信息」配置：目标规模（默认 80，10–500）、最多反问轮数（2–6，默认 6）、可反问维度（库存 / 销量 / 利润率 / 履约时效 / 商品效期 / 售后支持 / 发放形式 / 商品偏好，默认全选）；目标群体、人数与预算为必问，不在此配置 | 前台 AI 多轮反问：候选 ≤ 目标规模或问满轮数即出结果；只从勾选的维度里自动挑选（Prompt 7.6）；结果不截断 |

- 标语与主视觉：取页面装修 Banner 第 1 帧的标题与图片，不再单独填写。
- 排序：在场景列表中「上移 / 下移」，即时同步前台顺序。
- 上线 / 下线：在场景详情操作；上线前须引导词已发布、在售商品 ≥ 3 款。
- 自动下线：「上线中」的场景过了结束日期自动变为「已下线」，并写入变动记录；列表显示剩余天数，如「剩 18 天 · 到期自动下线」。
- 待上线场景到开始日期不自动上线，仍需手动上线（见十六）。
- 取消的字段：简称（默认取名称）、角标、细分用途、状态选择。

### 6.2 场景配置（AI 场景层）

每个场景一份配置，直接对应 Prompt v2.0 的「场景层」：

- 品类偏好：优先召回的品类及权重。
- 禁忌与要求：不推品类（如餐补不含烟酒）、包装要求、时效提示。
- 默认商品类型：礼包为主 / 卡券为主 / 爆品为主（均为 SKU，只影响排序）。
- 场景识别词：用户输入含这些词时自动识别为本场景（如「年货 / 春节 / 新春」）。
- AI 候选池：取 6.5 计算出的场景在售商品，不再单独按场景标圈品。

配置保存后可在后台「试一下」：输入一句需求，查看 AI 的反问轮次、候选数变化与选品结果预览，确认后再发布。

### 6.3 引导词

按「二级栏目」配置（每个场景、每个资源频道、专家咨询各一组）：

| 字段 | 说明 |
| --- | --- |
| 输入框提示语 | 如「说说年货怎么发，例如「120 位员工发年货，人均 300」」 |
| 收缩态提示 | 默认取提示语「例如」之前的部分，可改 |
| 引导问句（1–6 条） | 可新增、删除、上移排序，前台按顺序展示；普通问句点击后填入输入框；填空句用 {人数:120} 标出可改的空与默认值 |
| AI 生成 | 按场景名称、有效期与在售商品生成 3 版，选一版填入编辑框后再改 |
| 空的候选值 | 每种空（人数 / 预算 / 份数 / 面值…）的常用值，全局维护 |

校验：问句 ≤ 20 字；个人账号可见的问句不得含利润、会员价字样；发布时提示语与全部问句不得为空。状态：草稿 / 有未发布修改 / 已发布。

### 6.4 页面装修（场景页与资源频道页共用）

装修画布按 PC 前台 1440 宽版式绘制，与前台 Beta03 的二级场景页、资源频道页一一对应；手机端装修后续迭代。场景在「场景详情 › 页面装修」，频道在「频道详情 › 页面装修」，用同一套装修器。

| 模板 | 适用 | Banner 右侧的运营板块 | 可加组件 |
| --- | --- | --- | --- |
| 丰富型 | 节庆大促 | Banner 轮播（最多 5 帧）+ 场景专区 ×6（3 列 × 2 行） | 核心品牌 |
| 精简型 | 常驻场景、资源频道 | Banner + 专题方块 ×4（2 × 2） | 核心品牌 |

| 板块 | 坑位数 | 建议尺寸 | 前台表现 |
| --- | --- | --- | --- |
| Banner 轮播 | 1–5 帧 | 1053×600 | 自动轮播；第 1 帧的标题与图片同时作为场景标语与主视觉 |
| 场景专区 | 6 | 400×300（可选） | 链专题 / 品牌时自动露出 3 个商品缩略图 + 款数 +「进入专区」；自定义则展示图片 |
| 专题方块 | 4 | 300×200（可选） | 标题 + 副标题 + 商品数 |
| 核心品牌（组件） | 5 / 10 / 15 / 20 可选，每行 5 个 | 200×200 Logo（可选） | 品牌 Logo + 在售款数 |
| 系统板块 | — | — | 场景页：爆款 / 礼包 / 卡券栏目 + 商品列表；频道页：带筛选的频道商品；只展示，不可装修 |

- 链接目标：每个坑位都可选专题、品牌商品列表、自定义图片 + 链接（站内路径或白名单 https 域名）。
- 搜索选择：选专题可按名称搜、按状态（上线中 / 待上线 / 草稿）筛，已结束的不出现；选品牌可按名称、首字母、英文名搜，可只看「有在售商品」；单次最多显示 50 条。
- 模板与组件：切换模板需二次确认，已配置的坑位保留，切回可恢复；组件可添加、移除、上下移；核心品牌坑位数调小时，超出部分配置保留但不展示。
- 发布：空坑位前台自动隐藏；任何修改后状态为「有未发布修改」，PC 预览后发布，1 分钟内生效。
- 引用：装修引用的专题在专题「被引用」页签可见，引用中的专题不可删除；专题下线后该坑位前台隐藏并在工作台提醒替换。
- 权限：内容运营、超管可改；其他角色只读。

### 6.5 商品来源与商品明细

场景商品 = 绑定的商品池 ∪ 绑定的专题 ∪ 自定义规则命中 ∪ 手动加入 − 手动排除，计算方式与商品池、专题、频道归置共用一套（见 7.6）。

- 商品来源：勾选商品池与专题；可选补充自定义规则（货源、类目、品牌、商品类型、利润率下限）。保存前显示「保存后自动上架 N 款、自动下架 N 款」。
- 自动上下架：每小时按规则重算；商品下架或利润率低于阈值时自动下架，回升后自动上架；关闭后只在保存规则时生效。
- 商品明细：分段「在场景中 / 自动下架 / 手动矫正 / 近 7 天变动」，可按商品类型（爆品 / 礼包 / 卡券）和关键词筛选；每款商品显示进入方式与原因；可导出清单。
- 手动矫正：手动加入（多选，不设失效时间，不受规则自动下架影响）、手动排除（不再自动上架）、置顶；支持批量导入（7.6）。
- 自动上下架与矫正都写入变动记录，商品运营对场景商品只读。

### 6.6 场景推荐

- 可配置推荐开关、候选商品范围（默认取场景 / 频道的商品池）、缓存时长（个性化 30 分钟 / 通用 1 天）。
- 兜底文案与兜底商品（模型超时或校验失败时使用）由运营维护。
- 后台可查看推荐日志：模型输出、校验结果、是否走了兜底、点击率。

### 6.7 顶部广告位

AI 对话框上方的弧形轮播广告：图片、短标题、副标题、角标、跳转（场景 / 频道 / 专题 / 商品 / 外链）、投放时间、排序、定向人群；同时在线 ≤ 5 个。

## 七、资源管理

三层选品：**商品库**是平台全量商品的唯一来源 → **商品池**由运营按规则圈出通用商品集合 → **专题**在规则、商品池基础上排他、矫正。场景、资源频道绑定商品池或专题取品，页面装修的坑位链接到专题或品牌商品列表。前台和 AI 只能展示、召回商品库中「已上架」的商品。

### 7.1 商品库

**商品来源**：不再单独做货源管理，商品库用「货源」字段记录每款商品的来源：天猫超市、天猫优品、京东自营、妙鲤精选、入驻商家、发发卡券（虚拟商品）。第三方货源按接口定时同步价格与库存；入驻商家和卡券由供应商在其商品库录入后同步，运营管理后台不录入商品。商品类型（爆品 / 礼包 / 卡券）由供应商录入时指定、随同步进入商品库；审核时发现错误可纠正并记操作日志，已上架商品不可改。货源可作为商品库筛选项和选品规则条件。

**商品字段**（与前台商品卡、资源广场一致）

| 分组 | 字段 |
| --- | --- |
| 基本 | 商品 ID、SKU ID、名称、品牌（归一后）、类目（一级 / 二级）、规格、主图与详情图、69 码 |
| 价格 | 接口价（成本）、会员价、零售价、市场价、平均到手价、市场价利润率、税率 |
| 履约 | 仓类型（电商仓 / 商家仓 / 线上发放）、库存状态、可配送地区、起订量、是否支持七天无理由、是否一件代发 |
| 运营 | 商品类型（爆品 / 礼包 / 卡券，供应商指定，决定在前台哪个栏目展示）、运营标签（运营唯一需要打的标签，见 7.5）、上架时间、销量 |
| 卡券专属 | 面值档位、电子 / 实体、卡面图、有效期、兑换范围 |

**商品状态**：待审核 → 已上架 ⇄ 已下架；系统自动标记「异常」：货源下架、长期无货、价格倒挂（会员价 ≤ 接口价）、缺主图。异常商品自动从前台和 AI 候选池移除，并在工作台提醒。

**批量操作**：筛选后批量上下架、打 / 清运营标签、AI 打标建议、导出。筛选维度与前台「频道商品」一致（名称、品牌、是否有货、类目、库存地区、ID / SKU ID、价格利润区间、时间范围），另加货源、状态、运营标签、商品类型（爆品 / 礼包 / 卡券，带各自数量，方便运营了解前台展示）。

**商品数据标准化**：品牌归一（已完成）、类目模板（食品保质期、3C 型号，待建设）、补全 69 码；类目重复项（如「电脑、办公」与「电脑办公」）在后台做映射合并。

### 7.2 商品池

商品池是运营自定义的通用商品集合（如「年货精选池」「电子卡券池」），一次维护，被场景、资源频道、专题引用；池内商品变化自动同步到引用处。菜单：商品中心 › 商品池。

| 页签 / 字段 | 说明 |
| --- | --- |
| 基本信息 | 名称、说明、负责人、启用 / 停用；可复制为新池 |
| 商品规则 | 至少 1 条：货源 + 类目 + 品牌 + 商品类型 + 利润率下限；利润率 =（会员价 − 供货价）÷ 会员价 |
| 商品明细 | 在池中 / 自动下架 / 手动矫正 / 近 7 天变动；按爆品 / 礼包 / 卡券筛选；可手动加入、排除、置顶、批量导入、导出 |
| 被引用 | 列出引用它的场景、频道、专题；停用前提示影响范围 |

商品池列表显示池内款数及爆品 / 礼包 / 卡券各自数量。新品命中规则自动进池，商品下架或利润率不达标自动出池。

### 7.3 专题管理

专题是一组有主题的商品 + 一个落地页（/topic/{id}），可被场景、频道绑定为商品来源，也可作为页面装修坑位的跳转目标。不再区分「专题页 / 品牌馆」：按品牌圈品就在规则里选品牌；只展示某品牌商品时，装修坑位直接选「品牌商品列表」。

| 页签 / 字段 | 说明 |
| --- | --- |
| 基本信息 | 专题名称、封面 / Banner 图（1053×600）、开始 / 结束日期（留空为长期）、状态（草稿 / 待上线 / 上线中 / 已结束） |
| 商品规则与排他 | 绑定商品池 + 自定义规则（同 7.2）；一键排他：给任一规则打开「排他」，它命中的商品从专题结果中剔除 |
| 商品明细 | 在专题中 / 自动下架 / 排他剔除 / 手动矫正；手动加入、排除、置顶、批量导入、导出 |
| 被引用 | 场景、频道、场景装修、频道装修中引用它的位置 |

**排他规则**：用于在规则结果中排除部分商品。例：「居家焕新季」绑定「居家日用池」，再加一条排他规则「品牌 = 蓝月亮」，蓝月亮商品就从专题中剔除。

- 排他规则的货源可选「全部货源」，只按类目 / 品牌 / 商品类型匹配，不看利润率。
- 优先级：手动加入 > 手动排除 > 排他规则 > 普通规则 / 商品池；手动加入的商品不受排他影响。
- 被剔除的商品在明细中标注「排他：命中排他规则 N（条件）」；专题列表显示排他规则条数，可按「有排他规则」筛选。
- 被引用的专题不可删除；上线中的专题须先下线。

### 7.4 频道运营（发发福利·商品资源栏目）

一个资源频道由两个角色分工维护，频道详情分三个页签，各自保存、各自发布，互不覆盖。频道基本信息（内容运营新建）：频道名称、角标（如「自营」）、一句话卖点、排序、常显（前 5 个）/ 收入「更多频道」、可见范围（等级 / 权益包）。

| 页签 | 负责角色 | 配置内容 |
| --- | --- | --- |
| 商品归置 | 商品运营 | 三步：设置规则（绑定商品池 / 专题 + 货源规则，可多货源；筛选条件：货源、类目、品牌、商品类型、利润率）→ 预览与调整（手动加入、排除、批量导入）→ 发布生效；发布后提示下一步「页面装修」 |
| 页面装修 | 内容运营 | 见 6.4，频道默认精简型（Banner + 专题方块 ×4）+ 核心品牌组件 |
| 引导词 | 内容运营 | 见 6.3，1–6 条问句 |

发布校验：频道归置数为 0 时不得上线；装修引用的专题已下线时提示替换。下线频道不影响已下单订单。

### 7.5 品牌与标签

- **品牌管理**：只维护品牌档案——品牌名、英文名、首字母、Logo、启用 / 停用；不做授权管理。品牌详情显示在库商品和规则里选了该品牌的相关专题；仍有商品的品牌不可删除，只能停用。
- **标签**：运营只给商品打运营标签，不打其他标签（商品类型、类目、品牌等属性以货源为准）；字段：名称（≤ 6 字）、标签类型、使用说明、来源（人工 / AI 建议采纳）、启用状态；删除时从已打标商品上同步移除。
- **标签类型**（标签管理的第二个页签，即运营标签的分组）：类型名称、说明、前台商品卡是否展示、是否参与 AI 打标 / 推荐、启用状态。预置：场景标、节日标、人群标、营销标。类型下仍有标签时不可删除；改名同步到其下全部标签。

### 7.6 统一选品口径与批量导入

商品池、专题、场景、频道归置用同一套计算：结果 = 规则命中 ∪ 绑定商品池 ∪ 绑定专题 ∪ 手动加入 − 手动排除 − 排他规则命中（仅专题）。同一商品只计一次，并记录进入方式（规则 N / 商品池 / 专题 / 手动）。

批量导入出现在所有手动加商品的位置（场景、商品池、专题的商品明细与添加抽屉，频道归置第 2 步）：

1. 下载模板（商品 ID / SKU 编码）。
2. 上传 Excel / CSV。
3. 逐行校验：可导入 / 已存在 / 无此商品 / 已下架。
4. 确认导入可导入的行，失败明细可下载；导入的商品记为「手动加入」。

### 7.7 素材库

统一管理商品图、品牌 logo、卡面、Banner、专题图；按类型、品牌、上传人筛选；显示被引用位置，被引用的素材不可删除。三类占位图（商品图、品牌 LOGO、卡面）由系统预置，缺图时自动使用。

## 八、订单管理

### 8.1 订单结构

- 一次结算生成一个**主订单**，按货源 + 发货仓拆为若干**子订单**；发货、售后、开票都以子订单为单位。
- 订单来源标记：AI 方案（记录方案 ID 与对话 ID）/ GUI 频道 / 专题 / 品牌商品列表 / 场景页 / 集采咨询转单，用于统计各入口成交。
- 仅企业账号可产生订单。

### 8.2 订单状态

| 状态 | 进入条件 | 后台可操作 |
| --- | --- | --- |
| 待支付 | 提交订单，需在线支付补差 | 关闭；超时 30 分钟自动关闭并释放账户冻结 |
| 待发货 | 支付成功（含账户全额抵扣） | 取消并退款（须用户同意或供应商无货）、催发货 |
| 部分发货 | 部分子订单已发货 | 查物流、催发货 |
| 已发货 / 已发放 | 全部子订单发货；卡券卡密已发放 | 查物流 / 发放记录、补发卡密 |
| 已完成 | 签收后 7 天自动确认；电子卡券发放即完成 | 开票跟进 |
| 已关闭 | 未支付超时、主动取消、全额退款 | — |

子订单叠加「售后中」标记，不打断主状态。签收后超过售后期（默认 15 天，可按货源配置）不再受理售后。

### 8.3 订单列表与详情

- **筛选**：订单号 / 子单号、企业、下单人、货源、状态、来源入口、支付方式、下单时间、金额区间、是否售后中、开票状态。
- **详情**：商品明细（会员价、数量、小计）、支付构成（活动账户 / 商品预付款 / 在线支付）、收货方式（单地址 / 名单代发到员工）、子订单、物流信息（8.4）、发票、售后记录、操作日志。
- **名单代发**：展示名单导入文件、每个收件人的发货状态；异常地址可修改后重发。
- 后台不展示、不记录服务商对其客户的报价（利润差价为服务商自有信息）。

### 8.4 订单物流

物流按子订单分包裹跟踪，轨迹由货源方接口回传。入口：订单列表「查看物流」（有运单或卡密的订单才显示）、订单详情「物流信息」卡片。

| 子单情况 | 展示内容 | 可操作 |
| --- | --- | --- |
| 待发货 | 待供应商填写运单；备货节点；超 48 小时标红 | 催发货 |
| 已发货（整批） | 物流公司、运单号、状态（运输中 / 已签收）、轨迹时间线（最新在上） | 复制运单号 |
| 名单代发 | 包裹总数 / 已签收 / 运输中 / 异常统计；收件人明细（姓名、电话脱敏、状态、签收时间） | 导出全部包裹明细、处理异常包裹（通知供应商并短信告知收件人） |
| 电子卡券 | 卡密发放记录：已发放 / 已兑换 / 未兑换，发放渠道（短信 + 站内信） | 补发卡密 |

一个订单有多个子单时按「子单 N · 货源」切换。物流异常（地址异常、超时未揽收）进入工作台待办。

### 8.5 开票

按子订单开票，礼包按子商品明细开具。开票申请、人工上传、财务系统自动回传与红冲见 5.7 发票管理；订单详情展示发票状态与下载。

### 8.6 集采咨询单

前台商品卡「集采咨询」、「批量集采咨询」和无货商品的咨询均生成咨询单。

| 状态 | 说明 |
| --- | --- |
| 待跟进 | 新提交；工作日 4 小时内须跟进 |
| 跟进中 | 已联系，记录沟通内容 |
| 已报价 | 录入报价：单价、起订量、交期、有效期；用户前台可见 |
| 已转订单 | 用户接受报价并下单，关联订单号 |
| 已关闭 | 用户放弃 / 报价过期，须填关闭原因 |

字段：商品（可多个）、预估数量、期望交期、定制需求、联系人、跟进人、沟通记录。

## 九、售后管理

### 9.1 售后类型

| 类型 | 适用 | 说明 |
| --- | --- | --- |
| 仅退款 | 未发货、少件、商品问题且无需退货 | 退款金额 ≤ 该商品实付 |
| 退货退款 | 已签收，支持七天无理由或质量问题 | 用户寄回，供应商签收后退款 |
| 换货 | 破损、错发 | 供应商重新发货，不动资金 |
| 卡券售后 | 未激活卡密退卡、卡密异常补发 | 已兑换卡密不可退 |

名单代发订单可按收件人维度申请售后。

### 9.2 处理流程

1. 用户在前台对子订单发起售后，选择类型、商品与数量，填原因、上传凭证。
2. **供应商先审**：48 小时内同意 / 拒绝（拒绝须写原因）；超时未处理自动升级为平台介入。
3. **平台介入**：用户对拒绝结果不满意可申请介入；客服查看双方凭证后裁定（支持用户 / 支持供应商 / 部分退款），裁定为最终结果。
4. 退货类：用户填写退回物流 → 供应商确认收货 → 触发退款。
5. **退款**：金额超过阈值（如 ¥5,000，待确认）须财务复核；退款按支付构成原路回到各账户，见 9.3。

售后单状态：待供应商处理 → 待用户退货 → 待供应商收货 → 退款中 → 已完成；分支：已拒绝、平台介入中、用户已撤销。

### 9.3 退款回账户规则

- 按原支付比例拆分退回：在线支付部分原路退回，商品预付款部分回预付款账户，活动账户部分退回活动账户。
- 退回时活动金已过期的，按平台规则延长 30 天有效期（待确认）。
- 积分账户不参与订单支付，售后退款不涉及积分。
- 已开票的子订单退款后，自动生成红冲任务（见 5.7）。

### 9.4 售后规则配置

按货源配置：售后期、是否支持七天无理由、供应商处理时效、自动升级介入时长、退款复核阈值、运费承担规则。

### 9.5 售后看板

售后率（按货源 / 商品 / 供应商）、平均处理时长、介入率、超时数；售后率异常的商品可一键下架。

## 十、全链路流程与数据联动

&#91;embedded content: 全链路 · 三条线在前台汇合\]

用户与资金、商品与内容两条线由运营在后台准备，在前台汇合成交；交易线从结算开始，售后退款再回到账户。

### 10.1 关键联动规则

| 触发 | 联动结果 |
| --- | --- |
| 企业认证通过 | 开通等级默认权益包 + 三个账户；前台立即显示会员价、利润与下单入口 |
| 权益包变更 | 可见资源频道、价格口径、可用支付账户即时变化；AI 召回池同步收缩 / 扩大 |
| AI 功能使用 | 按 AI 开发团队规则扣减积分；后台积分入口可查消耗明细 |
| 商品下架或异常 | 从商品池、专题、场景、频道、场景推荐和 AI 候选池自动移除；已在购物车的提示失效 |
| 页面装修 / 频道归置 / 专题发布 | 前台频道栏、场景页 / 频道页坑位 1 分钟内更新；收缩态导航同步 |
| 场景配置发布 | Prompt 场景层与引导词更新；场景推荐缓存失效 |
| 下单 | 账户冻结 → 支付成功扣款；记录来源入口与 AI 方案 ID |
| 用户申请开票 | 生成开票申请 → 财务人工上传（后续：推送财务系统，开票完成自动回传）→ 通知用户下载 |
| 售后退款完成 | 按原支付比例回活动 / 预付款 / 在线支付；已开票的生成红冲任务；售后率计入商品与货源 |
| 商品池 / 专题规则变化 | 引用它的场景、频道、专题按新结果自动上下架，并写入各自变动记录 |
| 场景有效期到期 | 上线中的场景次日 0 点自动下线，前台场景栏与对话框上下文同步隐藏 |
| 专题下线 | 引用它的装修坑位前台隐藏，工作台提醒内容运营替换 |

### 10.2 工作台待办

待审核企业认证、待认账 / 待认领流水、待复核（调账 / 发放 / 退款）、待开票、待介入售后、待跟进集采咨询、异常商品、即将到期的场景 / 专题、装修引用已下线专题、物流异常包裹、定时任务告警（附 AI 异常摘要）。待办按当前账号的角色、业务线与数据范围过滤；超时项标红。

### 10.3 核心数据

GMV 与订单数（按来源入口：AI 方案 / 频道 / 专题 / 品牌商品列表 / 场景页）、新增企业与认证通过率、预付款充值额、活动账户发放与核销率、售后率、集采咨询转单率。

## 十一、角色业务操作流程（培训用）

用于给客户运营、商品运营、内容运营、财务做后台培训。每张图是该角色的日常主流程，按编号顺序操作；高亮框是最容易出错、需要重点讲解的关卡。订单 / 客服的售后流程见 9.2。

### 11.1 客户运营

&#91;embedded content: 客户运营 · 8 步\]

要点：第 4 步驳回必须选驳回原因模板并短信通知；第 8 步冻结账号须另一人复核。对应菜单：客户中心、交易中心 → 集采咨询单。

### 11.2 商品运营

&#91;embedded content: 商品运营 · 8 步\]

要点：第 3 步价格倒挂、缺图的商品不能上架；第 1 步商品类型（爆品 / 礼包 / 卡券）由供应商录入时指定，第 3 步审核时可纠正；第 4 步运营只打运营标签；第 5 步商品池一改，引用它的场景、频道、专题都会自动上下架，停用前先看「被引用」；第 6 步三步式发布，发布后提醒内容运营做页面装修；第 2–4 步可用「AI 商品打标建议」批量处理；手动加商品处都可批量导入。对应菜单：商品中心（商品库 / 商品池 / 类目 / 品牌 / 标签）、发发福利 → 频道运营 → 商品归置、数据与智能 → 定时任务中心。

### 11.3 内容运营

&#91;embedded content: 内容运营 · 8 步\]

要点：新建场景只填名称和有效期，到期自动下线，待上线的要手动上线；第 3 步可用「AI 引导词与文案生成」起草，个人账号可见的引导词不得出现利润、会员价；第 5 步的排他规则只用于从专题结果中剔除商品，手动加入的不受影响；第 6 步场景和频道用同一套装修器，选专题 / 品牌先搜索，空坑位前台自动隐藏；新增可点击的坑位要确认已有埋点。对应菜单：发发福利 → 场景管理、频道运营 → 页面装修 / 引导词、专题管理、广告位；商品中心 → 素材库。

### 11.4 财务

&#91;embedded content: 财务 · 8 步\]

要点：认领、调账、发放、退款都是一人发起、另一人复核；第 6 步上传发票后由「AI 发票 OCR 回填」自动识别，差异项标红后确认；对接财务系统后改为自动回传，人工上传保留兜底。对应菜单：账户与财务。

## 十二、AI 应用

后台 AI 面向内部员工，目标是减少 11.x 流程中最费人工的步骤。菜单位于「数据与智能 → AI 应用」，各应用同时以按钮形式嵌在对应业务页面。

### 12.1 三条规则

1. **AI 只给建议，人确认才生效**：资金、售后裁定、上下架、发布永不由 AI 自动执行。
2. **全量留痕**：每条建议记录输入、输出、模型版本、操作人采纳 / 修改 / 放弃，用于计算采纳率。
3. **成本归平台**：后台 AI 消耗计入平台内部成本，不扣客户积分账户；各应用可设每日调用上限。

### 12.2 首期应用

| 应用 | 使用角色 | 入口 | 输入 → 输出 | 人工确认方式 |
| --- | --- | --- | --- | --- |
| 商品打标建议 | 商品运营 | 商品库批量操作、频道商品归置 | 商品标题、类目、品牌、价格 → 标准化标题、品牌归一、类目映射、建议运营标签与建议商品池，附置信度 | 列表逐条或批量勾选采纳；置信度低于阈值的默认不勾选 |
| 引导词与文案生成 | 内容运营 | 引导词、专题、Banner、广告位编辑页 | 场景 / 频道、商品范围、往期点击数据 → 提示语、三条问句（含填空句）、专题标题与副标题、Banner 文案，各 3 版 | 选一版后可改，仍走草稿 → 预览 → 发布；自动校验个人账号可见文案不含利润、会员价 |
| 发票 OCR 回填 | 财务 | 发票管理 → 上传发票 | 发票文件 → 发票代码、号码、日期、金额、税额、抬头、税号；与开票申请比对差异 | 识别结果回填表单，差异项标红，财务确认后保存 |

### 12.3 后续应用（P1 / P2）

价格 / 库存异常巡检摘要（与定时任务结合）、场景层配置建议、集采咨询单回复与报价草拟、客户流失预警、认账模糊匹配、对账差异归因。

### 12.4 AI 应用管理

- 开关：按应用 × 业务线 × 角色启停。
- 日志：调用次数、耗时、失败率、采纳率、修改率；可按应用 / 操作人 / 时间查看单条详情。
- 评估：采纳率连续 2 周低于 30% 的应用在工作台提示产品复盘。

## 十三、定时任务中心

菜单：数据与智能 → 定时任务中心。首期支持三类监控：商品监控、订单监控、埋点监控。

### 13.1 创建规则

| 项 | 规则 |

## 十四、埋点规则与埋点管理

埋点**自建**，覆盖前台 AI 对话、前台发发福利 GUI 界面与运营后台。目的：分析用户行为，归因每笔成交来自哪个入口（AI 方案 / 引导词 / 频道 / 专题 / 品牌商品列表 / 装修坑位），并支撑自然语言查数与埋点监控。

### 14.1 采集方案

- 前端 SDK：自动采集页面浏览与停留时长；关键交互用代码埋点主动上报。
- 上报：批量异步上报到自建日志服务，失败本地缓存重试；入数仓后 T+0（分钟级）可查。
- 关联：用 session\_id、plan\_id（AI 方案）、order\_id 把行为与订单、商品、账户打通。
- 服务端事件：支付成功、订单创建、退款等以服务端上报为准，不依赖前端。

### 14.2 命名规范

- 事件名：`{业务线}_{页面}_{对象}_{动作}`，全小写下划线，如 `fafa_res_card_click`、`admin_invoice_upload_submit`。
- 业务线：fafa（发发福利）、jicai（发发集采）、fct（分采通）、admin（运营后台）。
- 动作枚举：view（页面浏览）、expose（曝光）、click、switch、input、submit、success、fail。
- 曝光口径：元素 ≥ 50% 可见且持续 ≥ 1 秒，同一页面生命周期内同一元素只报一次。

### 14.3 公共属性（每条事件必带）

| 属性 | 说明 |
| --- | --- |
| event\_time / event\_id | 事件时间、唯一 ID |
| user\_id / company\_id / account\_type | 用户、企业、个人 / 企业（未登录用设备 ID） |
| biz\_line | 业务线 |
| session\_id | 会话 ID，30 分钟无操作重置 |
| column / channel\_id / scene\_id | 当前栏目、频道、场景 |
| ui\_mode | 对话框展开 / 收缩态 |
| page / referrer | 当前页面与来源页面 |
| app\_version / platform | 版本、PC / H5 |

### 14.6 运营后台事件

配置发布（admin\_config\_publish，含对象类型与版本）、AI 建议采纳（admin\_ai\_suggest\_adopt / modify / reject）、导出（admin\_export\_submit）、资金操作发起与复核、定时任务创建与告警处理、自然语言查数提问（只记问题类型，不记结果数据）。

### 14.7 归因规则

- 订单归因入口取同一会话内、该商品「加购或立即下单前最后一次点击」的来源（AI 方案 / 引导词 / 频道 / 专题 / 品牌商品列表 / 装修坑位 / 场景页 / 搜索）。
- 来自 AI 方案的订单记录 plan\_id，可追溯到对话与引导词。
- 归因结果写入订单「来源入口」字段（8.1）。

### 14.8 埋点管理（后台功能）

| 功能 | 说明 |
| --- | --- |
| 事件字典 | 登记事件名、含义、触发时机、属性及是否必填、负责人、所属业务线；状态：草稿 → 待开发 → 已上线 → 已废弃；按版本留存变更 |
| 上报质量 | 各事件上报量趋势、必填属性缺失率、未登记事件列表 |
| 实时调试 | 输入用户 ID 或设备 ID，查看最近事件流，用于测试验收 |
| 监控 | 与定时任务中心的埋点监控模板联动（13.2） |

研发流程：需求评审时产品在字典登记事件 → 开发按字典实现 → 测试用实时调试验收 → 上线后状态改为已上线；未登记的事件不入正式数仓。

### 14.9 隐私与合规

不采集手机号、证件号、银行账号等敏感信息；输入框内容只记字数与来源，不记原文（AI 对话内容由对话日志单独管理）；明细数据保留 13 个月，汇总数据长期保留；隐私政策中说明行为数据的采集与用途。
