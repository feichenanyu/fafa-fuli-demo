首页营销运营位

顶部营销条从 5 个点击区合并成一整条运营位，点进档期场景的主推方案

①点运营位任意位置

业务说明

为什么改原营销条是「标题块 + 3 张方案卡 + 本档期上新」，共 5 个点击区，和下方场景区的方案重复，视觉分散，也没法按一个投放位统计效果。
规则
  • 一次只讲一个档期主题，整条只有一个落地
  • 运营可配：标签、标题、副标题、按钮文案、配图（最多 3 张）、落地（场景 + 方案）
  • Demo 演示开关「时令营销条」关闭后整条不显示
待确认
  • 多个档期并行时，是轮播还是只投一个
  • 是否按会员分群投放不同运营位
  • 运营位点击是否纳入埋点（建议纳入）
2

推广素材入口

场景卡左侧的素材区原来像装饰图；改成看得出能点、点了能预览并合成商城二维码

②点任意一张海报

业务说明

为什么改场景卡左侧有两个点击区：「查看方案详情」（主）和推广素材（次）。素材原来没有标题、没有悬停反馈，底部白条像空按钮，会员看不出能点。
设计取舍
  • 主次：方案详情是主按钮，素材区是次级入口，不抢主按钮
  • 可点提示用「说明文字 + 名称 + 悬停反馈 + 二维码示意」四重信号，而不是再加按钮
  • 点海报直接进入素材库并预览该海报，少一步查找
业务价值会员拿素材发朋友圈 / 客户群，海报带自己商城的二维码，扫码回流到商城成交。
3

商品列表多选 · 批量操作

所有商品列表都能勾选和全选，底部批量条统一处理询价、加购、上架、下单、代发

④批量下单 / 批量代发

业务说明

覆盖范围首页 / 方案页爆品货盘、货盘详情、模板详情、卡券「员工能换什么」、资源广场、搜索结果、店铺页；购物车原本就有勾选。勾选状态在各列表间共享，跨页面选的商品可以一起提交。
规则
  • 卡券只能代发、不能上架：批量上架时自动跳过并提示件数（V1.0 Spec：卡券显示「仅支持代发 · 不可上架」）
  • 代发按会员价从预付款扣款，同一批次按来源拆子单
  • 开通阿里权益的会员，猫超 / 优品商品下单时按 SKU ID 换成自有同品
为什么做年货节服务商一次要处理几十款商品，逐个点上架、下单效率低；批量操作是"整盘上架 / 整盘代发"之外的灵活选法。
4

批量上架 · 最低利润率

批量上架时设一个最低利润率，低于门槛的商品本次不上架

③批量上架
②选 ≥30%
④确认上架

业务说明

口径会员价利润率 =（市场价 − 会员价）÷ 市场价，与商品卡上的「利润率」是同一个数。
规则
  • 门槛只决定"上不上"，售价仍按定价方式计算（定价基准由会员自己选）
  • 没有市场价的商品算不出利润率，设了门槛就一并跳过
  • 门槛默认「不限」，与原来的上架流程完全一致
为什么做服务商整盘或批量上架时，可以一次把低利润商品挡在商城外，不用上架后再逐个下架。
待确认低于门槛的商品，除了"跳过"，是否还要支持"自动提价到门槛后上架"。
5

商品详情 · 同品 / 相似品

商品网格可直达详情；详情页说明这件商品还有哪些货源（同品）和可替代的商品（相似品）

①点商品名
②切到「相似品」
②点相似品
返回后点「同品对比」

业务说明

同品同一 SKU（条码一致 / 商家映射 / SKU ID 对应），换货源、商品不变。
  • 专供店同品：会员选「用平台」或「用专供店」，专供店缺货时自动回平台
  • 阿里权益自有同品：开通自有猫超 / 优品的会员，下单和上架按 SKU ID 自动替换，企业支付宝付款（V1.0 Spec）
相似品同末级类目 + 价格在当前商品 ±30% 以内 + 商品标签有重合（任务拆解 · AI 选品业务规则），换的是商品本身。
  • 只做推荐，不自动替换；专供店相似品需会员点「换成它」确认
  • 用途：无货替代（V3-8.1）、找利润更高的同类商品；对应「相似品推荐组件」（1.2-11）
Demo 与正式版差异
  • Demo 只有一级类目，末级类目暂按商品名推断；正式版取商品库末级类目
  • Demo 商品标签少，「标签重合」用于排序（同货盘、同标签排前），没有作为硬性条件
待确认
  • 匹配不到自有同品时，按平台货源下单还是拦住不让下单（V1.0 Spec 待定项）
  • 相似品是否严格要求三个条件同时满足
  • 京东相似品 API 接入后，与平台规则推荐如何合并排序
6

大货盘（1 万款）

一个货盘有上万款商品时：分页浏览、两级全选、按操作设上限，上架转后台任务

②全选本页
②全选全部 10,000 款
批量上架
滚到底部
提交后翻页

业务说明

分页与全选
  • 商品列表一律分页，前端只渲染当前页
  • 全选分两级：先本页，本页选满后再出现「全选全部筛选结果」，防止误操作
  • 正式版「全选全部」提交的是筛选条件 + 排除项，由后端按条件取数，不在前端传上万个商品 ID
各操作上限
  • 批量上架：不限数量；超过 500 件转后台上架任务，完成后在工作台「上架任务」查看结果、下载跳过明细（低于利润率、卡券、商城已有）
  • 批量下单 / 代发：单次最多 200 款（代发还要乘以名单人数，量更大）
  • 批量加购：最多 200 款；批量询价：一张询价单最多 50 款
为什么这样分上万款的典型用法是"整盘铺到员工商城，让员工自己选"，所以上架放开；下单 / 代发是真实扣款和发货，单次量必须可控，大批量走上架或分批更稳。
待确认
  • 200 / 50 / 500 这几个上限是演示假设，需要和交易、履约确认
  • 大货盘是否需要类目筛选、利润率筛选（筛选后再全选）
  • 上架任务失败重试、部分成功时的通知方式
  • 搜索、资源广场在万级商品下改为服务端分页（Demo 未覆盖）
