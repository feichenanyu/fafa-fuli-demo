六、场景管理

场景管理决定前台「精选福利场景」下每个二级场景的页面和卖哪些商品。内容运营在场景详情里按页签维护：页面装修｜商品来源｜商品明细。

6.1 场景基本信息

新建场景只填 2 项，其余配置都在详情页签里完成。

字段 说明 前台生效
场景名称 必填，如「新春年货节」 场景频道栏
有效期 开始日期 + 结束日期；常驻场景打开「长期有效」，不填结束日期 到期次日 0 点自动下线
  • 标语与主视觉：取页面装修 Banner 第 1 帧的标题与图片，不再单独填写。
  • 排序：在场景列表中「上移 / 下移」，即时同步前台顺序。
  • 上线 / 下线：在场景详情操作；上线前须在售商品 ≥ 3 款。
  • 自动下线：「上线中」的场景过了结束日期自动变为「已下线」，并写入变动记录；列表显示剩余天数，如「剩 18 天 · 到期自动下线」。
  • 待上线场景到开始日期不自动上线，仍需手动上线（见十六）。
  • 取消的字段：简称（默认取名称）、角标、细分用途、状态选择。

  • 搜索选择：选专题可按名称搜、按状态（上线中 / 待上线 / 草稿）筛，已结束的不出现；选品牌可按名称、首字母、英文名搜，可只看「有在售商品」；单次最多显示 50 条。

6.5 商品来源与商品明细

场景商品 = 绑定的商品池 ∪ 绑定的专题 ∪ 自定义规则命中 ∪ 手动加入 − 手动排除，计算方式与商品池、专题、频道归置共用一套（见 7.6）。

  • 商品来源：勾选商品池与专题；可选补充自定义规则（货源、类目、品牌、商品类型、利润率下限）。保存前显示「保存后自动上架 N 款、自动下架 N 款」。
  • 自动上下架：每小时按规则重算；商品下架或利润率低于阈值时自动下架，回升后自动上架；关闭后只在保存规则时生效。
  • 商品明细：分段「在场景中 / 自动下架 / 手动矫正 / 近 7 天变动」，可按商品类型（爆品 / 礼包 / 卡券）和关键词筛选；每款商品显示进入方式与原因；可导出清单。
  • 手动矫正：手动加入（多选，不设失效时间，不受规则自动下架影响）、手动排除（不再自动上架）、置顶；支持批量导入（7.6）。
  • 自动上下架与矫正都写入变动记录，商品运营对场景商品只读。

6.7 顶部广告位

场景首页顶部的弧形轮播广告：图片、短标题、副标题、角标、跳转（场景 / 频道 / 专题 / 商品 / 外链）、投放时间、排序、定向人群；同时在线 ≤ 5 个。

七、资源管理（节选：商品池）

7.2 商品池

商品池是运营自定义的通用商品集合（如「年货精选池」「电子卡券池」），一次维护，被场景、资源频道、专题引用；池内商品变化自动同步到引用处。菜单：商品中心 › 商品池。

页签 / 字段 说明
基本信息 名称、说明、负责人、启用 / 停用；可复制为新池
商品规则 至少 1 条：货源 + 类目 + 品牌 + 商品类型 + 利润率下限；利润率 =（会员价 − 供货价）÷ 会员价
商品明细 在池中 / 自动下架 / 手动矫正 / 近 7 天变动；按爆品 / 礼包 / 卡券筛选；可手动加入、排除、置顶、批量导入、导出
被引用 列出引用它的场景、频道、专题；停用前提示影响范围

商品池列表显示池内款数及爆品 / 礼包 / 卡券各自数量。新品命中规则自动进池，商品下架或利润率不达标自动出池。

前台展示（商品池页签，10-22 新增）：场景运营页业务栏目（爆款限定 / 精选礼包 / 福利卡券）下的筛选项和卖点标签在货盘（商品池）里维护，引用本池的场景 / 频道直接读取，保存后 1 分钟内同步。

字段 说明
栏目副标题 每个业务栏目 1 条，如「爆款限定：福利精选 · 独立 SKU」
筛选项名称 前台筛选按钮文字，如「休闲零食」「¥150–300」「电子卡」
卖点标签 按钮右侧小标签，≤ 6 字，如「618 同价」「低于商超」「卡密即发」；必须是可核实的事实（价格对比、发货方式、价保周期），不用「最低价」「第一」等绝对化用语
匹配条件 筛选项对应的商品范围：类目 / 价格区间 / 卡券形态，只能引用本池商品字段
显示 开关；关闭后前台隐藏该筛选项

场景绑定多个商品池时，按「商品来源」中排在第一的池展示；没有配置时前台只显示「全部」。卖点标签与筛选项的增删改写操作日志。

7.9 商品池定价规则（10-23 新增，10-26 改版）

位置：商品中心 › 商品池 › 详情 ›「定价规则」页签。取消独立的「定价模板」，定价规则直接写在商品池里：商品池同时管「卖什么」和「卖多少钱」，场景 / 频道只绑定商品池。会员价不是商品的固定字段，而是按用户所在业务系统与场景实时算出；前台只显示「会员价」，不另设「场景价」。首期不叠加会员等级折扣。

① 生效的业务系统：同一个商品池可对多套业务系统生效——发发福利 / 发发集采 / 分采通 / 企业终端采购，每个业务系统一套定价（默认加价率、条件规则、底价、顶价、取整各自独立）。未启用的系统不能引用本池；停止生效时该系统下的规则保留，引用本池的场景 / 频道不再使用本池商品与价格（需二次确认）。

② 每套系统的基础设置

字段 说明
基准价 固定为接口价（供应链给到平台的价格）
默认加价率 未命中任何条件规则时使用；会员价 = 接口价 ×（1 + 加价率）
最低毛利（底价） 底价 = 接口价 ×（1 + 最低毛利）；取整后低于底价时向上取整到底价；接口价上涨导致触底的商品自动从本池在该系统下架，进工作台待办「定价触底商品」
顶价 ≤ 市场价 / ≤ 平均到手价 / 不限；超过顶价的按顶价封顶
取整 不取整 / 到角 / 到元 / 尾数 9

③ 条件规则：每条规则 = 条件 + 加价率，条件可组合，不选即不限：

条件 说明
类目 多选叶子类目
品牌 多选启用中的品牌
货源 多选：京东自营 / 天猫超市 / 1688 / 供应商直供 / 卡券等
市场价利润率区间 ≥ 下限、< 上限，可只填一端；利润率 =（市场价 − 接口价）÷ 市场价

规则按顺序自上而下匹配，命中第一条即停，都不命中用默认加价率；运营可上移 / 下移调整优先级。列表显示每条规则实际命中的商品数（已被上面规则命中的不重复计）。例：休闲食品且利润率 ≥ 42% → +15%；其余休闲食品 → +10%；三只松鼠 / 良品铺子 → +12%；京东自营的低毛利粮油（利润率 < 20%）→ +6%；其余 +10%。

④ 价格预览：池内商品在当前系统下的接口价、市场价利润率、命中规则、会员价、毛利率与状态（正常 / 顶价封顶 / 触底下架）。接口价、利润率仅商品运营 / 财务 / 管理员可见。

⑤ 场景 / 频道取价

  1. 场景 / 频道属于哪个业务系统，就用所绑商品池在该系统下的规则（发发福利前台 → 发发福利规则）。
  2. 同一 SKU 出现在场景绑定的多个商品池时，取最低价；场景详情新增只读的「会员价」页签，逐个商品显示价格来自哪个池、命中哪条规则，调价需到对应商品池。
  3. 不在任何已绑定池内的商品（如全站搜索结果）用平台默认加价率（+12%）。
  4. 规则修改后 1 分钟内生效；已下单的订单按下单时的价格快照不变；所有修改记操作日志。

首期加价率均为演示数字，待商务确认。

十、工作台（节选）

10.2 工作台待办

待审核企业认证、待认账 / 待认领流水、待复核（调账 / 发放 / 退款）、待开票、待介入售后、待跟进集采咨询、异常商品、即将到期的场景 / 专题、装修引用已下线专题、物流异常包裹、定时任务告警（附 AI 异常摘要）。待办按当前账号的角色、业务线与数据范围过滤；超时项标红。

10.3 核心数据

GMV 与订单数（按来源入口：AI 方案 / 频道 / 专题 / 品牌商品列表 / 场景页）、新增企业与认证通过率、预付款充值额、活动账户发放与核销率、售后率、集采咨询转单率。

十四、埋点规则与埋点管理

埋点自建，覆盖前台 AI 对话、前台发发福利 GUI 界面与运营后台。目的：分析用户行为，归因每笔成交来自哪个入口（AI 方案 / 引导词 / 频道 / 专题 / 品牌商品列表 / 装修坑位），并支撑自然语言查数与埋点监控。

14.1 采集方案

  • 前端 SDK：自动采集页面浏览与停留时长；关键交互用代码埋点主动上报。
  • 上报：批量异步上报到自建日志服务，失败本地缓存重试；入数仓后 T+0（分钟级）可查。
  • 关联：用 session_id、plan_id（AI 方案）、order_id 把行为与订单、商品、账户打通。
  • 服务端事件：支付成功、订单创建、退款等以服务端上报为准，不依赖前端。

14.2 命名规范

  • 事件名：{业务线}_{页面}_{对象}_{动作}，全小写下划线，如 fafa_res_card_click、admin_invoice_upload_submit。
  • 业务线：fafa（发发福利）、jicai（发发集采）、fct（分采通）、admin（运营后台）。
  • 动作枚举：view（页面浏览）、expose（曝光）、click、switch、input、submit、success、fail。
  • 曝光口径：元素 ≥ 50% 可见且持续 ≥ 1 秒，同一页面生命周期内同一元素只报一次。

配置发布（admin_config_publish，含对象类型与版本）、AI 建议采纳（admin_ai_suggest_adopt / modify / reject）、导出（admin_export_submit）、资金操作发起与复核、定时任务创建与告警处理、自然语言查数提问（只记问题类型，不记结果数据）。

14.7 归因规则

  • 订单归因入口取同一会话内、该商品「加购或立即下单前最后一次点击」的来源（AI 方案 / 引导词 / 频道 / 专题 / 品牌商品列表 / 装修坑位 / 场景页 / 搜索）。
  • 来自 AI 方案的订单记录 plan_id，可追溯到对话与引导词。
  • 归因结果写入订单「来源入口」字段（8.1）。

14.8 埋点管理（后台功能）

功能 说明
事件字典 登记事件名、含义、触发时机、属性及是否必填、负责人、所属业务线；状态：草稿 → 待开发 → 已上线 → 已废弃；按版本留存变更
上报质量 各事件上报量趋势、必填属性缺失率、未登记事件列表
实时调试 输入用户 ID 或设备 ID，查看最近事件流，用于测试验收
监控 与定时任务中心的埋点监控模板联动（13.2）

研发流程：需求评审时产品在字典登记事件 → 开发按字典实现 → 测试用实时调试验收 → 上线后状态改为已上线；未登记的事件不入正式数仓。

14.9 隐私与合规

不采集手机号、证件号、银行账号等敏感信息；输入框内容只记字数与来源，不记原文（AI 对话内容由对话日志单独管理）；明细数据保留 13 个月，汇总数据长期保留；隐私政策中说明行为数据的采集与用途。

十五、非功能需求（节选）

15.1 非功能需求

类别 要求
安全 后台账号强制二次验证；敏感字段（手机号、信用代码、银行账号）列表脱敏，查看明文留痕
资金一致性 所有账户变动先写流水再改余额，支持按流水重算余额；日对账差异为 0 才算关账
同步时效 第三方货源价格库存至少每 30 分钟同步一次；下单前实时校验价格与库存
配置生效 发布后 1 分钟内在前台生效；支持一键回滚到上一次发布
性能 列表页 10 万条内筛选 ≤ 2 秒；导出超过 5 万条走异步任务
审计 操作日志保留 ≥ 3 年；资金类日志不可删除
合规 出版物须校验《出版物经营许可证》；个人账号任何接口不得返回成本与会员价
