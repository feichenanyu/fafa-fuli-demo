一、文档说明

本 PRD 定义帮帮采首期的会员前台和运营后台「帮帮采」应用，面向研发、测试与运营。范围与优先级以《帮帮采 首期产品 Spec v0.1》为准，小帮的选品边界以《帮帮采 AI 选品 Prompt》为准，话术沿用《小帮对话话术规范》。Demo 见画布「帮帮采 Demo v0.1」「运营管理后台 Demo v1.2」。

名词 含义
帮帮采 面向企业终端采购人员的 AI 采购产品；本文简称 BB
小帮 帮帮采的 AI 采购助手
三大应用 福利采购、行政采购、办公采购；固定不可增删
子场景 应用下的运营单元（如春节 / 年货福利、茶水间补货、新员工入职），决定类目范围、追问维度、快捷语
热门运营场景 首页卡片：榜单（如年货爆品 TOP100）或清单模板
任务 一次采购对话：从说需求到下单；在左侧「最近任务」可回看
接口价 供应链给平台的价格，定价基准；仅商品运营 / 财务 / 管理员可见
会员价 用户看到并支付的价格 = 接口价 ×（1 + 加价率）
市场价利润率 （市场价 − 接口价）÷ 市场价；上品和定价的条件
预付款账户 企业对公转账充值的货款账户，不支持退回；平台底座统一
AI 积分 企业使用小帮的额度；不抵货款

二、产品结构

帮帮采新增的只有会员前台和后台的「帮帮采」应用；客户、订单、账户、供应链接入都复用平台底座。

[embedded content: 帮帮采产品结构 · 5 层]

商品从供应链同步进商品库，按规则自动上架并定价；小帮只从已上架商品里选品，用户确认后订单与扣款走平台底座。

三、会员前台

3.1 整体布局

全站最左侧固定菜单栏（宽 232），右侧是当前视图：首页、任务页、订单、企业账户。

区域 内容 规则
Logo 帮帮采 · 企业采购 AI 助手 点击回首页
新建采购 主按钮 回首页、清空输入与子场景选择
导航 首页 / 福利采购 / 行政采购 / 办公采购 / 订单 / 企业账户 点应用 = 回首页并切到该应用
最近任务 最近 6 条，标题 + 应用 + 时间；圆点：进行中（品牌色）/ 待确认下单（橙）/ 已完成（灰） 点击恢复任务页，右侧定位到最近产出（订单 > 汇报 > 方案）
账户卡 企业名、预付款余额、AI 积分 实时同步；不显示活动账户

3.2 首页

首页只做一件事：让用户 5 秒内知道「说一句就能开始」。自上而下：

  1. 标题 + 欢迎语：欢迎语随当前应用切换，来自后台「三大应用」。
  2. 三大应用切换：福利采购 / 行政采购 / 办公采购，默认福利采购。
  3. 子场景标签：展示当前应用下上线中的子场景，按后台排序；带角标的显示角标（如「节日」）。点选 = 选中（再点取消），输入框示例与快捷语切到该子场景。
  4. 输入框：placeholder = 子场景第一条快捷语，未选子场景时用应用的输入框示例；Enter 发送，Shift+Enter 换行；空内容发送时提示「先说说要买什么」。
  5. 快捷语：最多 4 条，点击直接作为需求发送。
  6. 未完成任务提醒：存在未下单且非本次创建的任务时显示：「你上次的『{任务名}』还没下单，报价明天到期，要继续吗？」[继续上次] [新建采购]。只提一条。
  7. 热门运营场景：4 张卡片（名称、副标题、所属应用、角标热 / 新），点击创建任务并进入任务页，右侧直接定位「榜单 / 选品」。

发送后的分流：命中超范围词（机票、酒店、手机等）→ 小帮说明能帮的范围并给三大应用选项；没有数字也识别不出子场景 → 小帮给子场景选项；其余按关键词识别子场景（优先当前应用），进入任务。

3.3 任务页：三栏

栏 宽度 内容
左 232 全站菜单（同 3.1），当前任务高亮
中 520 AI 工作流：任务头（标题、应用 · 子场景、本任务已用积分）+ 5 步进度条 + 对话流 + 底部输入框
右 自适应 任务产出物与操作区：方案 / 选品清单（热门场景为「榜单 / 选品」）/ 汇报 / 下单四个页签

进度条 5 步：理解需求 → 补全信息（显示问了几轮）→ 选品出方案（显示几套）→ 确认下单 → 完成。当前步高亮，已完成步浅色。

3.4 AI 工作流（loop）

小帮每一轮都先观察已知与缺失，再判断是追问还是出方案；用户在任何时候调整，都回到判断这一步。

[embedded content: 小帮 loop · 2 个循环，1 个用户确认点]

上循环补信息（最多 2 轮），下循环调方案（不限次数）；只有确认卡被用户点下才会生成订单。

追问规则

  • 追问维度来自子场景配置；先从用户原话提取（人数、人均 / 总预算、到货天数、周期、品牌、具体商品名词如「投影仪」「墨盒」），已说过的不问。
  • 每轮 ≤ 2 问，必填优先；必填都有后，最多再问 1 轮非必填（只问 1 个）；总追问 ≤ 2 轮。
  • 问题卡：每个问题一组选项，全部选完自动提交；底部「不确定，你先推荐 →」用场景默认值补齐并出方案。品牌问题的选项 = 「没有」+ 子场景内采购量前 3 的品牌。
  • 追问前先复述已理解的信息（「好的，春节 / 年货福利，20 人、人均 ¥200。」）。
  • 用户说「随便 / 你看着办 / 不确定」→ 不再追问，用默认值并在方案回复里说明。

处理过程（对用户可见）：每条小帮消息上方用 2–4 行展示：✓ 已知 / ○ 还缺 / ! 跳过的商品及原因（如「膳魔师保温杯只剩 12 件，不够 20 份，已换成同类」）。不展示候选数量、不用技术词。

消息类型

类型 何时出现 形态
追问 信息不足 文字 + 问题卡；只有最新一条可操作
方案 信息补齐 / 调整后 处理过程 + 结论（首推、人均或合计、差额、送达日）+ [生成汇报方案] [调整方案] [直接下单]
调整 点「调整方案」 [更省钱一点] [品质再好一点] [只要最快到货]
留痕 右侧改数量 / 换品 / 移除 / 加入 / 导出 灰底小字；连续修改合并为最新一条；超预算附 [换便宜一点]
确认卡 点任何「下单」 方案、商品金额、运费、收货、发票、支付 6 行 + 按钮
完成 下单成功 订单号、扣款构成、送达日

底部输入框：随时可说「改成 25 人」「换便宜点」「做成汇报」「就要这个」；解析到数字 / 偏好就重出方案，提到汇报走生成汇报，提到下单出确认卡；追问中输入视为回答。

3.5 右侧：任务产出物与操作区

方案：顶部 A / B / C 方案切换（名称 + 总价，首推带角标）。汇总卡：总价、人均 × 人数（福利）或商品种数（行政 / 办公）、方案说明、预算条（超预算变橙）、剩余 / 超出金额、预计送达日。商品行：缩略图、名称、品牌 · 货源 · N 天达、会员价（划线市场价）、数量步进器、小计、[换一款]（展开同类目 3 款）[移除]。底栏：合计 + [导出清单] [生成汇报方案] [下单]。

选品清单 / 榜单：当前子场景类目内的已上架商品；筛选：类目、货源（京东自营 / 天猫超市 / 1688 / 得力直供）、2 天内到；排序：按采购量 / 价格从低到高。卡片显示排名（前 3 红色）、近 30 天企业采购量、库存提示（仅剩 N 橙 / 无货红）、[加入 X 方案]；未出方案时按钮为「先出方案」不可点。

汇报：标题、格式（PPT 6 页 / 分享页）、分享状态；指标卡：方案总价 / 预算 / 对比预算；需求复述；明细表；推荐理由 3 条。分享链接 7 天有效，只读、不能下单。

导出清单：导出当前方案为 Excel（商品、品牌、货源、会员价、数量、小计、合计、报价有效期），对话留痕；不扣积分。

3.6 下单与支付

「下单」页签：收货方式（统一送到公司 / 按名单发到员工 +¥6/人，后者仅福利采购）、发票（增值税专用 / 普通）、商品金额、运费、支付方式（预付款账户 + 余额）、应付、[提交下单确认]。

  • 运费：全部京东自营 / 天猫超市或商品金额 ≥ ¥299 包邮，否则 ¥12；名单代发按 ¥6/人。
  • 确认卡：任何入口的下单都先在对话中出确认卡；按钮 [确认下单 · ¥X] [再看看]。
  • 预付款不足：确认卡显示「预付款 ¥A + 在线支付补差 ¥B」，按钮 [在线支付补差并下单] [先去充值预付款] [再看看]。无活动账户、无账期。
  • 下单成功：生成订单号 BByyMMdd…，扣预付款，对话给出完成消息，右侧显示订单卡；发票签收后开出。
  • 报价有效期 7 天，到期前 1 天站内提醒；下单时按当时会员价重算，变价在确认卡提示。

3.7 订单与企业账户

  • 订单：列表（标题、订单号、时间、商品种数、支付方式、实付、状态）；详情、物流、售后、开票复用平台底座订单能力。
  • 企业账户：只有两张卡——预付款账户（余额、说明、[对公转账充值]，按企业专属汇款识别码到账自动入账）和 AI 积分（余额、消耗规则、按任务的消耗明细、[查看权益与额度]）。不显示活动账户。

四、运营后台：帮帮采应用

4.1 菜单与权限

帮帮采与发发福利在同一运营管理后台，作为「业务应用」下的新应用：客户、订单、财务、系统设置复用平台底座。顶栏「业务线」新增「帮帮采」，切换后打开帮帮采商品库；进入帮帮采任一页面时业务线自动显示为帮帮采。

菜单 页签 可编辑角色
商品库 商品 / 自动上下架规则 / 定价规则 超管、商品运营
场景运营 子场景 / 三大应用 超管、内容运营
热门运营场景 — 超管、内容运营
应用设置 — 超管（仅超管可见）

菜单可见：超管、商品运营、内容运营；不可编辑的角色只读。接口价、利润率、毛利率仅商品运营 / 财务 / 超管可见，其余角色显示 ***。所有新增、修改、上下线、手动下架记操作日志。

4.2 商品库 › 商品

帮帮采独立商品库，不区分商品类型。商品由供应链同步进来，是否上架、卖多少钱都由规则自动决定。

  • 指标卡：在库商品、已上架、自动下架、手动下架。
  • 页签 / 筛选：全部 / 已上架 / 已下架；商品名 / 品牌、货源、类目。
  • 列：商品（编号 · 同步时间）、类目 · 品牌、货源、接口价、会员价（自动）、定价命中（「规则 3 · +5%」或「默认 +8%」）、上品规则、状态（已上架 / 已下架 + 原因）。
  • 状态原因（按优先级判定）：手动下架 → 供应链已下架 → 连续无货 3 天 → 未命中上品规则（写明差在哪，如「未达『天猫超市 · 福利食品与家居』条件：利润率 6.7% < 15%」）→ 会员价低于底价 → 自动上架。
  • 操作：查看（接口价、市场价、利润率、会员价、命中规则、库存、采购量、被引用的子场景）；[手动下架]（填原因，之后规则不再把它上架）/ [恢复自动]；页头 [立即同步供应链]。
  • 商品不能在这里新增或改价。

4.3 商品库 › 自动上下架规则

规则决定从哪些供应链、哪些商品自动上架。规则之间是「或」：命中任一启用规则即上架。每天 06:00 全量跑一次，价格 / 库存变化实时触发。

字段 说明
规则名称 必填
供应链货源 多选：京东自营 / 天猫超市 / 1688 / 得力直供 / 供应商直供；至少选 1 个
类目 多选，不选 = 全部
排除品牌 这些品牌不自动上架
市场价利润率 ≥ %
接口价 ≤ 元，留空不限
近 30 天销量 ≥ 供应链侧销量，过滤冷门品
库存要求 有货才上架 / 不限
自动下架条件 多选：供应链下架 / 连续无货 3 天 / 价格倒挂 / 利润率低于下限
状态 启用 / 停用；列表可直接开关

列表显示每条规则「命中上架」商品数。删除 / 停用提示：只靠这条规则上架的商品会在下次同步时自动下架。

4.4 商品库 › 定价规则

会员价 = 接口价 ×（1 + 加价率）。商品自动上架后即按此设会员价，接口价变动时实时重算，1 分钟内前台生效。

  • 默认定价（页头 [修改默认加价 / 底价 / 顶价]）：默认加价率（演示 +8%）、最低毛利（演示 3%，底价 = 接口价 ×（1 + 最低毛利））、顶价（≤ 市场价 / ≤ 平均到手价 / 不限）、取整（不取整 / 到角 / 到元 / 尾数 9）。
  • 条件规则：类目、品牌、货源（均多选，不选 = 不限）、市场价利润率 ≥ / <（可只填一端）、加价率、备注；下限须小于上限，加价率不能为负。
  • 命中：自上而下匹配，命中第一条即停；都不命中用默认。列表显示顺序、条件、加价率、命中商品数（不重复计），支持上移 / 下移。
  • 顺序：先取加价 → 顶价封顶 → 取整 → 低于底价则取底价；若底价高于市场价（顶价为「≤ 市场价」时），该商品自动下架并进工作台待办。
  • 演示规则：① 货源 1688 → +15%；② 类目礼品卡 → +2%；③ 类目办公设备 → +5%；④ 休闲零食且利润率 ≥ 35% → +12%；其余 +8%。

4.6 热门运营场景

首页热门卡片。字段：名称、角标（无 / 热 / 新）、副标题、关联子场景（决定所属应用和商品范围）、类型（榜单 / 清单模板）、排行规则（近 30 天企业采购量 / 会员价从低到高 / 新上架优先）、TOP N、投放期、排序。列表显示近 30 天点击；支持上线 / 下线；首页最多展示 4 个上线中的，按排序。

五、数据与埋点
